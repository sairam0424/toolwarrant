# CLAUDE.md

toolwarrant is a control plane in front of the agentgateway v1.6.0 MCP gateway: it crawls upstream MCP servers, stores every tool definition as an immutable version identified by the SHA-256 of its RFC 8785 canonical JSON, lets a named person approve one exact digest, and enforces that approval at the gateway as an ExtMCP processor (strict mode: a tool is served only while the live definition hashes to the approved digest). Nothing is served until approved, a crawl never approves anything, and everything an upstream sends is hostile.

## Stack

Go 1.27 (`go.mod`: `go 1.27`, `toolchain go1.27.2`), one module `github.com/sairam0424/toolwarrant`, pure Go (modernc.org/sqlite, no cgo). Dependencies: gowebpki/jcs (RFC 8785), modernc.org/sqlite, google.golang.org/grpc v1.86.0-dev, google.golang.org/protobuf v1.36.12, golang.org/x/text, hiddeco/sshsig v0.2.0 (the OpenSSH `sshsig` envelope of the signed records) and golang.org/x/crypto v0.58.0 (`ssh`, `ssh/agent`), modelcontextprotocol/go-sdk v1.8.0 (seam tools and tests only), pgregory.net/rapid (tests only, MPL-2.0). Lint: golangci-lint v2.14.0 with the repository `.golangci.yml`. Licence Apache-2.0; `THIRD_PARTY_NOTICES.md` is generated.

`-short` skips six tests: the three Unicode walks of `internal/textdiff`
(`TestEscape_everyRune`, `TestEscape_coversEveryRuneTheToolNameRuleForbids`,
`TestNames_noSuspiciousRuneHasAnEmptyName`), two slow catalog tests
(`TestVerifyAudit_PagesThroughLargeLogs`,
`TestRecordCrawl_LargeCrawlDoesNotBlockADecision`) and the processor's gRPC size
test (`TestServe_AcceptsAPageOverGRPCsDefaultLimit`); the CI `test-full` job
runs those three packages without `-short`.

The `-short` policy: a test may consult `testing.Short()` only when its full run
exceeds thirty seconds on the runner per the timing table; every such test is
named in CLAUDE.md and runs in full in `test-full`. The timing table is the
"tests slower than 1s" step of the `test` and `test-full` jobs (gotestsum
v1.13.0 runs `go test` with `--jsonfile`, then `gotestsum tool slowest
--threshold 1s` writes every test over one second, slowest first, to the step
summary, also after a failure); `make test-timings` prints the same table
locally. `TestShortPolicy_everyShortSkipIsNamedInCLAUDEAndRunsInFull` in
`internal/shortpolicy` parses every Go file of the module, not only the test
files, and fails when a test or fuzz target consults `testing.Short()` without
being named in this file or without its package on the `test-full` command line,
and when anything else consults it: a helper, a method, `TestMain`, a benchmark,
or any function in a file without the `_test.go` suffix (a shared helper there
would otherwise hide the skip).

The seam scripts and the end-to-end test need the v1.6.0 release binary at `.cache/agentgateway-darwin-arm64` (gitignored; `TOOLWARRANT_GATEWAY_BIN` overrides the path) and the seam scripts need the four seam binaries in `bin/`. Outside the seam scripts and `make e2e` (which starts the gateway on loopback ports it picks itself and stops it) the gateway binary may only be run with `--validate-only`. The e2e scenarios share one stack and depend on each other's end state, so run the whole `TestEndToEnd`, not one subtest. Anything over two minutes runs in the background with output to a file.

The CI workflow is `.github/workflows/ci.yml`, triggered by every pull request and every push to main: lint (gofmt, go vet, golangci-lint, `scripts/gen-confusables.sh --check` against the committed UTS #39 table, and actionlint on the five workflow files; `TestConfusablesCI_lintJobRunsTheCheck`), vet and build, the short test suite under `-race`, the three packages whose tests `-short` skips (`internal/textdiff`, `internal/catalog`, `internal/processor`) in full (both test jobs run `go test` through gotestsum v1.13.0, one line per package and the failed tests' output at the end, and write the tests slower than one second to the step summary), govulncheck, gitleaks, the notices check, the release configuration check (`make release-check`), and the documentation checks (every test name cited in README.md, SECURITY.md, CONTRIBUTING.md, CLAUDE.md, CHANGELOG.md, docs/ and seam/RESULTS.md must exist as a test function, every relative link must resolve). The e2e job runs on `workflow_dispatch` only, against the linux release binary checked against the recorded checksum; it passed on 2026-10-12. The `requalify` job runs on a dispatch whose inputs `gateway_version` and `gateway_sha256` name a candidate release and runs `scripts/requalify-gateway.sh --e2e` against it (`TestRequalifyCI_dispatchJobRunsTheScript`). The nightly workflow `.github/workflows/nightly.yml` is the flake radar: once a day (03:17 UTC) and on dispatch, its one job `flake radar: go test -race -count=10 -short` runs the short race suite ten times through gotestsum with no reruns, writes the tests slower than one second and every failure with its count of failing runs to the step summary and uploads the gotestsum json as an artifact; it is not a required check and no ruleset references it. ## Repository layout

- `cmd/toolwarrant`: operator CLI, a thin client of the internal packages; `run()` is driven in-process by tests, `main` only exits.
- `cmd/mockupstream`, `cmd/seamclient`, `cmd/seamgate`, `cmd/seamprocessor`: spike scaffolding for the seam tests and the e2e test; never deployed.
- `internal/catalog`: SQLite registry (schema v7; a v6 file, the first released schema, v0.1.0 to v0.3.x, is migrated in place on a read-write open, which every command but `serve`, `audit verify` and `audit list` makes, `list` and `show` included, and which adds the `signed_records` table and its four guards inside the one transaction `migrate` holds and rewrites nothing, so the audit head stays, while a read-only or forensic open of a v6 file returns `ErrSchema` naming `init` and never writes, `schemav7.go`, D22 (g); a v2, v3, v4 or v5 file from an unreleased build is refused with `ErrSchema` and must be re-initialised; no message advises deleting a released catalog); the only writer of lifecycle state and the audit log, in one transaction; per-crawl and per-server caps and the per-crawl cap on rejected entries, quarantine, proposal budget and its reset, each server's processor address, integrity checks (guard and table DDL, the no-delete, no-replace and positive-id guards, every checked read and write refusing a history row or audit row below id 1 (a forensic open reads past such a row, as it reads past a missing guard), and the absence of foreign triggers, views, unique indexes and unaccounted automatic indexes; the newest-decision rule and the newest audit entry for every approved version; the serving path (`Snapshot`, `Tools`, `Tool`) handing out digests anchored to verified entries and reading no definition bytes, while every path that reads the stored bytes behind a digest (`Approved`, `Versions`, `loadTool`) hashes them against the digest on every call with no memory (D21 (d)); the whole chain verified once at open and the suffix after the pin on every reload, every walk starting at the smallest possible seq, bound included, so a row at seq 0 or below is a chain break, with the locally computed hash of every decision entry kept in memory, so that the serving path and the decision path trust an audit entry only when its hash computed from its fields equals the one that walk recorded, never the stored hash column; every version's status and ever-approved flag reconstructed from the verified entries on every decision and in `Versions`, a rollback target accepted only when a verified approval or rollback entry names its digest; `Server` and `Servers` checked like every other view and anchored to the verified `server.processor_set`, `server.added` and newest `server.paused` or `server.resumed` entries, and the paused flag anchored on every path that acts on it (`Snapshot`, `RecordCrawl`, pause and resume); every tool's state column anchored to the newest verified lifecycle entry about the tool on every path that acts on it (`Snapshot`, `Tools`, `Tool`, `Approved`, the decisions, the crawl; `Approved` and `Snapshot` anchor every tool row of their scope before leaving one out, so an edited state cannot hide a tool from emit, export or the processor); the server row anchored to the first `server.added` entry, a second one reported by `Integrity`; `Approved` taking the approver from the verified entry, and `ApprovedWithHead` and `AuditHead` returning the head of the chain as the same read transaction verified it, the pin taken under the walk lock, so an export records the head of exactly the snapshot its approvals came from (D21 (e)); every checked read taking the walk lock before its first statement, so that a read snapshot never predates the pin it is compared with; the catalog identity and the file's device and inode compared on every read against a replaced file; `Integrity` verifying every entry's seal and link as it streams the log, comparing the row count with the entries walked, and cross-checking every mutable column and every subject the log describes). Since D22 (c) the operator trust list lives in the chain: `trust.bootstrap` and `trust.rotated` entries about `@trust` whose `signed_records` row the entry's `sigref` token binds (`signed.go`), written by `SetTrust` with the compare-and-set on the payload's `prev_head` inside the write transaction (`trust.go`: `TrustList`, `SigningState`, `Receipt`; `OpenOptions.TrustRoot` pins the bootstrap's signer and refuses a catalog without a bootstrap, both at the end of every walk, so a forensic open refuses on its first view), verified by every walk under the rules of `trustwalk.go` (the record binding, TUF's rotation rule at threshold 1, the entry's actor as the canonical name the list gives the key letter for letter, no `signed_records` row under an entry that carries no record, one primary-key range seek per walked page; every signed record once at open and only the appended ones on reload, none on a crawl-only reload) and reported by `Integrity` through `integrity_signed.go` (`SignedRecordsInvalid`, `SignedRecordsOrphaned`, `TrustListsInvalid`, the last counting too a pinned root over a log with no trust entry). The trust boundary is D14, D15 and D17: whoever can write the file can append a correctly sealed entry; a forger who rewrites an entry must rewrite every entry from it to the head, which a running `Store` catches through its pin, and which, made while no `Store` holds a pin (the CLI between commands, the processors while stopped), is caught by the recorded head, the git export (since D21 (e) signed and naming the head it mirrors, so the two anchors check each other through `export verify --expect-head`) and backups alone.
- `internal/lifecycle`: pure state machine (states, commands, events, `Serves`) and the exported digest-shape rule (`IsDigest`, `LastSeenVerifiable`) that the processor and the canary share; property-tested invariants.
- `internal/gate`: RFC 8785 canonicalisation and SHA-256 digest, profile `full-v1`; refuses inexact numbers and non-UTF-8.
- `internal/audit`: hash chain over audit entries (`Seal`, `Verify`, `VerifyFrom`, `Head`).
- `internal/crawl`: raw MCP Streamable HTTP `tools/list` client; vets every tool, quarantines, never approves.
- `internal/fetch`: the only egress path; SSRF-hardened dialer (connect-time address checks, DNS pinning, caps).
- `internal/processor`: ExtMCP gRPC processor; list filtering, call rule, caps, shared secret, digest cache, observed-evidence table sized from the snapshot, holding evidence for every catalog tool a page names (servable or not) and kept across a pause; an unreadable page marks every servable tool, a page the gRPC transport refuses for size is observed on the `CheckResponse` call and marks them too, and a page seen while the snapshot is empty (paused server) is judged against the names already tracked; a replaced catalog file is a source error; `Config.MaxEvidenceAge` ages only listing evidence that agrees with the approval (a contradiction denies until a clean page, D21 (a)) and `Config.MaxCrawlAge` (default off) denies a call whose only allowing evidence is a crawl older than the age as `crawl evidence too old` (`Stats.CallsStale`, the `stale` field of the stats line). Listener TLS (`Config.TLS`): TLS 1.3 forced on a copy of the caller's configuration, server-only or with a client CA that then authenticates the hooks in place of the shared secret (O-2, D19); a configuration with no certificate or with client verification against no authority is refused.
- `internal/emit`: agentgateway v1.6.0 config emitter; gateways form with a loopback bind, listener inputs, explicit allow rules, failClosed, sha256 header, `Verify`, validation with the gateway binary, the request-header filter on every processor entry, refusal of a processor address on one of the gateway's own sockets (compared with the input's own bind and listener addresses; a host that is a name rather than an IP literal is refused on any port the gateway binds, since a name may resolve to this host) and of a numeric-looking host that is not an IP literal; the loopback aliases common resolvers map without DNS count as loopback. The gateway's `backendTLS` block on a processor entry (`Server.TLS`, D19): all four fields or none, absolute printable-ASCII paths on the gateway host that the emitter never opens, a DNS hostname (an IP literal is refused), written after the request-header filter and before the metadata where the canary reads it; the gateway's `--validate-only` opens the three files, so validating with the binary needs them on the emitting host.
- `internal/export`: mirror of approved definitions into a directory and git; crash-safe manifest (version 3, with the verified audit head and the digest profile), Ed25519 signing of the manifest (`ReadSigningKey`, `MaxKeyFileBytes`) and `Verify` of a directory against the operator's public key (D21 (e)).
- `internal/signing`: the OpenSSH `sshsig` records of the signed decisions (D22 (a)): `Sign` and `Verify` over github.com/hiddeco/sshsig with the namespace a package constant (`NamespaceDecision`, `NamespaceTrust`; `NamespaceHead` reserved), so no caller string and no empty namespace reaches the library; `Sign` verifies its own output under the signer's key before returning it, `Verify` applies the key policy and compares the embedded key's fingerprint with the one the record names before the cryptography and refuses any message hash but sha512, an ssh-rsa signature made with anything but rsa-sha2-512 (`RSASignatureAlgorithm`) and a blob that is not the canonical encoding of the signature it parses to (one signature, one byte form, one `RecordDigest`); `Unarmor` reads the `-----BEGIN SSH SIGNATURE-----` block from the first byte, as `ssh-keygen` requires; the two payload types (`Decision`, type `toolwarrant/decision/v1`, and `TrustList`, type `toolwarrant/trust-list/v1`) are marshalled once to RFC 8785 bytes that are signed, stored and verified verbatim and parsed only after the signature verified, the parsers reading `type` first and accepting exactly those bytes (no whitespace, other key order, unknown or missing key, non-canonical number or field over its cap); `RecordDigest` is the `sigref` token an audit entry carries; `CheckKeyPolicy` accepts ssh-ed25519, the two sk- types, the three NIST curves and ssh-rsa from 3072 bits and refuses ssh-dss and certificates; `OpenAgent` dials ssh-agent under the socket rules (the value of SSH_AUTH_SOCK only, a unix socket of this uid that is private itself or inside a private directory, under the sun_path bound, the dial and the key list bounded by `AgentTimeout`, a `Sign` bounded by the caller's context) and `ReadPrivateKeyFile` reads an unencrypted OpenSSH key under the export key's file rules generalised (a passphrase-protected key is refused with the agent named, no passphrase is ever read); `KeySource` reads one path as `ssh-keygen -Y sign -f` does: a public key means the agent, anything else a private key file. No function returns or prints private material; the fingerprint is the only key text an error carries. Two-way interop with the host's `ssh-keygen` is pinned by `TestOpenSSH_SignatureVerifiesWithSshKeygenAndTheReverse`, `TestSign_ProducesASignatureSshKeygenVerifiesUnderTheNamespace` and `TestVerify_AcceptsASignatureSshKeygenMadeAndRefusesItUnderAnotherNamespace`, which run on this host (OpenSSH 10.3p1) and on the ubuntu runners and skip with the reason where `ssh-keygen` is not on PATH. `internal/signing/sigtest` generates test keys and serves in-process agents (a keyring, and one that never answers a Sign) for the tests of this and later packages; no key material is in the tree, as with `internal/testcert`.
- `internal/trust`: the pure rules of the signed operator trust list (D22 (c)), importing `internal/signing` (payload shape, key line, key policy, the two namespaces) and `golang.org/x/text/unicode/norm` (the NFKC fold of the catalog's `normalizeActor`), no I/O and no package state. `Validate` turns a `signing.TrustList` into a `Record`: every name normalised by `NormalizeName` (the D7 rule of the catalog's `normalizeActor`, NFKC, lower-case, `^[a-z0-9][a-z0-9._@-]{0,63}$`, re-implemented so the package imports no catalog; pinned from both sides: `TestNormalizeName_AgreesWithCatalogsNormalizeActorTable` holds the catalog's table and the catalog's `TestNormalizeActor` runs `trust.NormalizeName` on every human row) and unique, every key parsed from its one canonical line, within `signing.CheckKeyPolicy` and unique by fingerprint, one to `signing.MaxSigners` operators, `Threshold` exactly 1 else `ErrUnsupportedThreshold` (O-14); every other function refuses a `Record` that `Validate` did not produce. The rotation rule is TUF's at threshold 1 (finding 10): `CheckBootstrap` wants version 1, a signer among the list's own keys and, when a root is pinned, that fingerprint (`ErrBootstrapVersion`, `ErrNotSelfSigned`, `ErrNotThePinnedRoot`); `CheckRotation` wants exactly version N+1 (`ErrRollback`, N and N+2 alike) signed by a key of both the list in force and the new list (`ErrSignerNotInBothLists`, so the last signer cannot remove itself and a list is never emptied); `State.Apply` folds `KindBootstrap` and `KindRotated` records in increasing seq order and refuses a second bootstrap (`ErrSecondBootstrap`), a rotation before one (`ErrNoList`), another event (`ErrKind`) and a seq out of order (`ErrSeqOrder`), returning a new `State` and leaving the receiver as it was. Authorisation is separate from validity (finding 6): `Record.Lookup` resolves a fingerprint to a name and `Record.Authorize` requires the key to be listed for exactly the entry's actor (`ErrUnauthorizedSigner`, `ErrAnotherOperatorsKey` naming both people). `AllowedSigners` renders the `allowed_signers` file stock `ssh-keygen -Y verify` reads, one line per key with `namespaces="decision@toolwarrant.invalid,trust@toolwarrant.invalid"`; `TestAllowedSigners_RendersOneLinePerKeyWithBothNamespacesAndSshKeygenAcceptsIt` runs it against the host's `ssh-keygen` for Ed25519, ECDSA P-256 and RSA-3072 under both namespaces and skips with the reason where there is none. Property tests (`TestProperty_stateAfterFoldingEqualsTheLastAcceptedRecord`, `TestProperty_rotationNeverLowersTheVersion`) and `FuzzRecordValidate` run in the full suite.
- `internal/textdiff`: escaped diff renderer and invisible-character findings for approvers, plus the UTS #39 look-alike and mixed-script findings (`Skeleton` over the generated `confusables_table.go`, `LookAlikeChanges`, `MixedScriptWords`, the `Look-alike changes` section of `Tool`; `gen_confusables.go` behind `//go:build ignore` regenerates the table from `third_party/unicode/confusables.txt`).

## Rules

- Conventional commits (`type(scope): subject`) with a WHY paragraph in the body; no `Co-Authored-By` trailer.
- Tests before commit: every behaviour change gets a test; gofmt, go vet and golangci-lint clean; `go test -race` on the touched packages; keep existing tests passing or say which design decision changed them.
- Nothing is pushed, tagged, published or registered without the owner.
- Keep "MCP" out of the product name; "toolwarrant for MCP" is the permitted form.
- Treat upstream text as hostile: `textdiff.Escape` in text mode, `strconv.Quote` in logs, never print tokens or credential-bearing URLs, fail closed.
- Read `seam/RESULTS.md` (including its post-review sections) and `docs/decisions.md` D10 to D21 before changing anything the gateway sees: `internal/emit`, `internal/processor`, `internal/extmcpv1`, `cmd/toolwarrant/verify.go`, `cmd/toolwarrant/probe.go`, `cmd/toolwarrant/liveadmin.go`, `cmd/toolwarrant/livecompare.go`, `cmd/toolwarrant/livetls.go`, `cmd/toolwarrant/servetls.go`.
- Documents cite tests by their exact names and state what the logs show, not what was expected; when a test is renamed, update every document that cites it (the CI `docs` job fails otherwise). Plain prose, no marketing language, no em dashes.
