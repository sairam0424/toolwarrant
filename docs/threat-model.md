# Threat model

This document adapts the ranked threat model of the design report (section 6.1,
written before any code existed) to what toolwarrant v0.1 actually is: a Go
control plane and ExtMCP processor over SQLite, in front of agentgateway v1.6.0,
with native MCP upstreams only, no LLM path, no OpenAPI or gRPC ingestion and no
redaction. Threats that exist only in the fuller design (description generation,
`$ref` dereferencing, gRPC reflection, response redaction) are not listed; they
are non-goals of v0.1 and the code has no surface for them.

Every control in the first table is traceable to a test in this repository or to
a numbered result in [../seam/RESULTS.md](../seam/RESULTS.md). Tests are cited
as the package name followed by the test function names; the packages live under
`internal/` except `cmd`, which is `cmd/toolwarrant`, and `e2e`, whose
`TestEndToEnd` runs the whole chain on the real agentgateway v1.6.0 binary
(scenarios A to P; `make e2e`; `demo/run.sh` keeps the last run in
`demo/last-run.log`). Where a control depends on the live gateway, the scenario
letter is the proof. The `docs` job of
[../.github/workflows/ci.yml](../.github/workflows/ci.yml) checks that every
test name cited in the documents exists in the tree, so a renamed test cannot
orphan a documented control. Rows 25 and 26 record what the end-to-end scenarios
O and P pin on the real gateway and, apart from that, what the second review's
lab saw beyond them. The fourth round (the fixes after the third review,
2026-10-11, decision D13 in [decisions.md](decisions.md)) changed rows 4, 11,
16, 18, 20, 21, 22, 25 and 26 and limits L1, L6, L11, L17, L18 and L19; where it
matters, a row says what held before it.

## Actors and trust boundaries

- The upstream MCP server is hostile. Everything it sends, including tool names,
  is attacker-controlled input to the crawler, the processor, the diff renderer,
  the exporter and every terminal an operator reads.
- The agentgateway binary and its configuration file are trusted to run the
  processor chain the file names. The file's header carries an unkeyed SHA-256
  of its body: tamper-evidence against accidental edits and against edits that
  leave the header alone, not a proof of origin (limit L19). Whoever edits the
  file can drop the guard, so the file has one owner, the operator records the
  body hash `emit` prints and gives it to the canary, and the canary checks the
  file, the recorded hash and the gateway's whole live configuration.
- The processor is part of the gateway's trusted computing base: its answer
  decides what is served. Whoever can reach its listener without the shared
  secret decides too.
- The gateway's admin listener is part of the trusted computing base as well.
  The emitted file binds it, with the stats and readiness listeners, to
  127.0.0.1, but the admin API is unauthenticated: it hands out the loaded
  configuration, shared secret included (`GET /config_dump`), and accepts a
  replacement configuration (`POST /api/config`) that the gateway applies and
  writes back to the watched file. Every local user of the gateway host is
  therefore inside the boundary (limit L18). `emit --disable-admin` turns the
  admin API off, at the price of the canary's live-configuration comparison.
- The catalog file is trusted only after its own checks: every approval handed
  out is re-hashed and must be what the newest approve or rollback decision
  about the tool in the append-only approvals table says (D13); guard objects
  must be present with the definition `init` wrote and no trigger or view the
  schema did not create may exist (checked at open and on every snapshot load);
  and the audit chain must verify. `Store.Integrity` in `internal/catalog`
  cross-checks every mutable column the log describes (approved digest,
  last-seen digest, state and proposal budget of every tool; paused flag,
  allow-private flag and URL hash of every server; every approval row) against
  the approvals table and the audit log and lists every disagreement, and
  `audit verify` runs it after the chain check (`integrity ok` or
  `integrity problem` lines, exit code 1 on any problem).
- Operators are named but not authenticated beyond the OS: `--as NAME` and
  `TOOLWARRANT_ACTOR` are honoured as given, after normalisation. Single tenant.
